## 🎯 Pattern Recognition Flowchart

### When You See a Problem:

```
1. Read Problem → Ask Yourself:

"What's the input?"
├─ Array? → Check: Two Pointers, Sliding Window, Binary Search
├─ Tree? → Check: DFS, BFS, Binary Tree patterns
├─ Graph? → Check: DFS, BFS, Union-Find, Shortest Path
├─ String? → Check: DP, Two Pointers, Sliding Window
└─ Numbers? → Check: Math, Bit Manipulation

"What's being asked?"
├─ Optimization? → Think: DP, Greedy, Binary Search
├─ Count ways? → Think: DP, Backtracking, Math
├─ Find all? → Think: Backtracking, DFS
├─ Order matters? → Think: Topological Sort, BFS
└─ Min/Max in stream? → Think: Heap

"Any constraints?"
├─ Time limit? → Need O(log n) or O(n)? → Binary Search, Heap
├─ Space limit? → Need O(1)? → In-place algorithms
└─ Range/Frequency? → Hash Map, Prefix Sum

2. Check Cheatsheet → Find Pattern → Apply Template
```

## 🆘 When Stuck

### Problem Too Hard?
```
1. Read cheatsheet.md for pattern
2. Look at similar easier problem
3. Check if hard.md has similar problem
4. Break into smaller sub-problems
5. Google the pattern (not the problem)
```

### Can't Find Pattern?
```
1. Re-read problem carefully
2. Try brute force first
3. Check COVERAGE_REPORT.md for similar problems
4. Draw examples on paper
5. Ask: "What would I do manually?"
```

### Optimization Stuck?
```
1. What's current complexity?
2. What's the bottleneck?
3. Can we use hash map? (Space for time)
4. Can we sort? (O(n log n) acceptable?)
5. Is there preprocessing? (Prefix sum, etc.)
```
